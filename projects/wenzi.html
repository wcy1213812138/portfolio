探索、投字与谜题

《字冢》是 C++17 与 Win32 控制台实现的文字 RPG。玩家通过字符地图辨认人物、门和机关，用 WASD 移动，用方向键投字攻击，并在不同场景中完成谜题、收集文字和推进剧情。

  1. 键盘输入
  2. 地图移动／投字／交互
  3. 谜题或战斗规则
  4. 主流程处理结果
  5. 地图与文字界面更新

主状态机组织流程

GameManager 使用 Menu、Run、MiniGame、Exit 四种状态。菜单处理开始与读档；Run 处理地图中的输入；MiniGame 把控制交给推箱或矩阵谜题。状态决定这一轮输入应该交给谁，避免地图移动和谜题输入同时执行。

进入新地图时，主流程组织角色位置、地图和相关战斗状态。剧情交互放在 WorldEvents.cpp，地图、谜题和战斗不直接承担全部剧情分支。

谜题返回状态，主流程发放结果

Puzzle 包含序列、推箱和矩阵规则。序列谜题通过目标顺序与是否限时配置，返回忽略、推进、错误、超时或完成等结果。推箱和矩阵返回 Running、Solved 或 Quit。

矩阵是 5×5 网格，操作一个位置会让中心及上下左右加一并循环；玩家把当前矩阵调成目标矩阵。规则模块判断是否完成，GameManager::ApplyPuzzle 再更新剧情标志、给出奖励和提示。

  1. MiniGame 接收输入
  2. Puzzle 更新当前谜题
  3. 返回 Running／Solved／Quit
  4. GameManager 更新标志和奖励
  5. 回到地图流程

投字与敌方行动通过报告衔接

Combat::ThrowWord 处理投字轨迹和命中对象，返回包含命中类型、格子编号和结果值的 AttackReport。主流程根据报告决定提示、谜题交互和剧情推进，而不是由战斗模块直接发放所有奖励。

一次成功移动或投字后，AfterMove 推进追逐者和 Boss 行动。追逐与 Boss 移动使用 BFS 相关逻辑；追逐者按玩家行动计数推进，Boss 行动返回是否命中玩家的报告。地图规则与回合节拍通过主流程联系起来。

  1. 方向键投字
  2. Combat：轨迹与命中
  3. AttackReport
  4. ProcessAttack：处理结果
  5. AfterMove：追逐者与 Boss 行动
投字与敌方行动 ↗ BFS 寻路 ↗

存档保存状态，渲染读取状态

存档写入地图编号、玩家坐标和剧情标志。读取时校验地图与坐标范围，并检查文件是否完整。主流程负责把读取结果恢复到游戏中。

字符绘制由 Render 完成，控制台清屏和读键封装在 Console 中。游戏规则更新地图与状态，渲染根据当前状态显示画面；底层控制台调用集中管理，避免散落到每个玩法模块。

  1. 地图、坐标、剧情标志
  2. SaveSystem 写入／读取校验
  3. GameManager 恢复游戏
  4. Render 与 Console 显示状态
